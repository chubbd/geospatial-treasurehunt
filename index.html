Query Greater London data from Overture Maps, materialised once per session into in-memory DuckDB-WASM — no backend needed. Full spatial SQL: ST_Distance, ST_Intersects, ST_Contains and more.

Quick start

1) Click ⚡ Init DuckDB to materialise London tables in memory.

2) Write SQL in the editor and run with ▶ Run SQL (or Ctrl/Cmd+Enter).

3) Review rows in 📊 Results; if latitude/longitude columns are present, points are plotted on the map.

SELECT name, category, lat, lon
FROM london.places
WHERE name IS NOT NULL
LIMIT 20;

How the map works

The map only plots query output when your SELECT includes latitude/longitude columns. Supported names are inferred from:

  • Latitude: lat, latitude, y, ylat
  • Longitude: lon, lng, longitude, x, xlon
SELECT ST_Y(geometry) lat, ST_X(geometry) lon
FROM london.places
LIMIT 20;
SELECT ST_Y(ST_CENTROID(geometry)) lat, ST_X(ST_CENTROID(geometry)) lon
FROM london.buildings
WHERE height IS NOT NULL
  AND ST_Y(ST_CENTROID(geometry)) BETWEEN 51.490 AND 51.520
  AND ST_X(ST_CENTROID(geometry)) BETWEEN -0.040 AND 0.010
ORDER BY height DESC
LIMIT 20;

Table guide: london.places

Point features for places with names, categories, addresses, and point geometry. Useful for restaurants, museums, amenities, postcode search, nearest-place workflows, and map labeling.

SELECT id, name, category, lat, lon
FROM london.places
WHERE name IS NOT NULL
LIMIT 25;
SELECT name, category, lat, lon
FROM london.places
WHERE category ILIKE '%restaurant%'
   OR category ILIKE '%cafe%'
   OR category ILIKE '%museum%'
ORDER BY name
LIMIT 40;
SELECT
  p.name,
  addr.freeform,
  addr.postcode,
  p.lat,
  p.lon
FROM london.places p
CROSS JOIN UNNEST(p.addresses) AS t(addr)
WHERE addr.postcode ILIKE 'EC1%'
ORDER BY addr.postcode, p.name
LIMIT 40;

Table guide: london.buildings

Building footprints with geometry plus useful attributes like height, floor count, footprint area, and centroid-style lat/lon fields. Great for tallest/large-building analysis and spatial containment/intersection.

SELECT name, height, num_floors, building_area_m2, lat, lon
FROM london.buildings
WHERE height IS NOT NULL
ORDER BY height DESC
LIMIT 20;
SELECT name, height, num_floors, building_area_m2, lat, lon
FROM london.buildings
WHERE height IS NOT NULL
  AND lat BETWEEN 51.490 AND 51.520
  AND lon BETWEEN -0.040 AND 0.010
ORDER BY height DESC
LIMIT 20;

Geospatial SQL examples

SELECT
  name,
  building_area_m2,
  ST_Area(geometry) AS geometry_area_native_units
FROM london.buildings
WHERE name IS NOT NULL
ORDER BY building_area_m2 DESC NULLS LAST
LIMIT 20;
SELECT ROUND(
  ST_Distance(
    ST_Point(-0.0866, 51.5045),
    ST_Point(-0.0754, 51.5055)
  ) * 111320,
  0
) AS approx_distance_m;
SELECT
  b.name,
  ROUND(ST_Distance(ST_Point(b.lon, b.lat), ST_Point(-0.0984, 51.5138)) * 111320, 0) AS approx_dist_m
FROM london.buildings b
WHERE b.lat BETWEEN 51.5048 AND 51.5228
  AND b.lon BETWEEN -0.1074 AND -0.0894
  AND ST_Distance(ST_Point(b.lon, b.lat), ST_Point(-0.0984, 51.5138)) * 111320 <= 1000
ORDER BY approx_dist_m
LIMIT 30;
SELECT
  b.name,
  b.height,
  ROUND(ST_Distance(ST_Point(b.lon, b.lat), ST_Point(-0.1278, 51.5074)) * 111320, 0) AS approx_dist_m
FROM london.buildings b
WHERE b.name IS NOT NULL
ORDER BY approx_dist_m
LIMIT 15;
SELECT name, height, building_area_m2
FROM london.buildings
WHERE ST_Intersects(
  geometry,
  ST_GeomFromText('POLYGON((-0.082 51.513, -0.078 51.513, -0.078 51.516, -0.082 51.516, -0.082 51.513))')
)
ORDER BY height DESC NULLS LAST
LIMIT 20;
SELECT name, height, building_area_m2, lat, lon
FROM london.buildings
WHERE ST_Contains(
  geometry,
  ST_Point(-0.0984, 51.5138)
)
LIMIT 10;
